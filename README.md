# enee759u-project

EDA/CAD Digital Circuits Design Space Exploration Project

## Purpose

This project is a design space exploration tool for digital circuits, developed for a class project on EDA/CAD for digital systems. The goal is to compare handwritten RTL designs with High-Level Synthesis (HLS) generated designs using Vitis HLS. Various HLS pragmas and configurations are explored, with resource utilization and performance metrics collected and analyzed. Ultimately, the project provides insight into trade-offs between RTL and HLS design methodologies through Pareto plot visualizations.

---

## Implementation Structure

The project has the following high-level structure:

- **mac/**:
- `MATLAB/low-pass.m`: Generates FIR model and data input/output files (`input.mem`, `output_15.mem`, `taps.mem`).
- `src/`: Handwritten RTL (Verilog/SystemVerilog) designs.
- `rtl-sim.sh`: Simulates handwritten RTL designs (iterative and parallel) using Icarus Verilog, verifying outputs against reference data from MATLAB.
- `C/`:
  - `floating_point/`, `fixed_point/`, `HLS/`: FIR filter implementations in C++ with their own Makefiles.
- `sweep_results.csv`: Aggregated HLS synthesis results.
- `plot.py`: Generates Pareto plots of design trade-offs from `sweep_results.csv` and includes hardcoded post-route implementation results.
- **pc/**:
  - `sweep.py`: Automates generation and sweeping of HLS C++ code, running C simulation (Csim) and C synthesis (Csynth) with various pragmas, parsing reports, and compiling results in `sweep_results.csv`.
  - `io/`: Includes `output_15.mem` generated by the MATLAB model for golden reference data.
  - `run_impl.tcl`: Batch runs Vivado implementations for chosen HLS test cases.
  - `parse_impl.py`: Parses Vivado implementation reports to append detailed post-synthesis results (optional; key results included directly in `plot.py`).

**Workflow Overview:**
1. Use MATLAB (`low-pass.m`) to generate `.mem` files for model verification.
2. Develop and simulate handwritten RTL (with `rtl-sim.sh`) and compare to MATLAB model.
3. Implement FIR filter in floating-point and fixed-point C++, and in HLS-compatible C++.
4. Use `sweep.py` to vary HLS pragmas, run Csynth for each config, and parse results into CSV.
5. (Optional) Run implementation (`run_impl.tcl`), parse reports with `parse_impl.py`, and hardcode main results into `plot.py`.
6. Generate comparative Pareto plots of area/speed trade-offs with `plot.py`.

## How to Run

### **Prerequisites**
- **MATLAB:** For initial model and .mem file generation.
- **Python 3:** For `sweep.py`, `plot.py`, and parsing scripts. Install common libraries: `matplotlib`, `pandas`, etc.
- **C++ Compiler:** To build C++ implementations.
- **Vitis HLS:** To perform HLS synthesis flows.
- **Vivado (optional):** For full post-route implementation.
- **Icarus Verilog:** For simulating handwritten RTL.

### **Directory Setup**
- Make sure directory structure matches the project root as outlined above.
- Place the generated `.mem` files from MATLAB in the `io/` directory.

### **Quick Demo: Simulate and Build All Implementations**
1. **Simulate Handwritten RTL (Iterative and Parallel):**
   ```sh
   cd mac
   ./rtl-sim.sh iterative
   ./rtl-sim.sh parallel
   ```
2. **Build FIR in C++:**
   ```sh
   cd C/floating_point
   make
   cd ../fixed_point
   make
   cd ../HLS
   make
   ```

### **Long Demo: Full HLS Sweep, Implementation, and Pareto Plot**
1. **Run HLS Sweep (may take several minutes):**
   ```sh
   cd pc
   python3 sweep.py
   ```
   - This varies HLS pragmas/clock constraints and updates `results/sweep_results.csv` with synthesis results.

2. **(Optional) Full Implementation (may take >10 minutes):**
   ```sh
   vivado -mode batch -source run_impl.tcl
   python3 parse_impl.py
   ```
   - Results are manually summarized in `plot.py` for convenience.

3. **Generate Pareto Plot:**
   ```sh
   python3 plot.py
   ```
   - Produces area/speed trade-off plots with both HLS sweep and (pre-filled) implementation data for thorough comparative analysis.

## Example Output

- Running `plot.py` generates plots showing resource utilization (e.g., LUTs, FFs, DSPs) versus performance (latency, throughput) for both handwritten RTL and a variety of HLS designs.
- `rtl-sim.sh` outputs a correctness comparison between handwritten Verilog and the MATLAB model.
- `sweep.py` and `parse_impl.py` aggregate hardware metrics for all tested HLS configurations.
